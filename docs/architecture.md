# 系統架構

## 1. 架構目標

本系統採前後端分離與模組化設計，目標是讓教學流程、資料處理、分析計算、報告產生與部署環境彼此解耦。

主要目標：

- 保留原系統，不產生相依或覆寫。
- 支援本機、校內伺服器、一般網站與雲端部署。
- 核心資料處理可重現、可測試、可追蹤。
- 教學流程可調整，不寫死在資料處理函式中。
- 儲存與資料庫可替換。

## 2. 高階架構

```text
瀏覽器
   ↓
前端 Web 應用
   ↓ REST API
後端應用服務
   ├── 身分與課程服務
   ├── 檔案匯入服務
   ├── 資料品質服務
   ├── 資料處理服務
   ├── 視覺化服務
   ├── 分析服務
   ├── 報告服務
   ├── 提示服務
   └── 稽核紀錄服務
        ↓
PostgreSQL
物件儲存
背景工作佇列
```

背景工作佇列初版可先保留介面，待大型檔案、PDF 產生或大量分析需要時啟用。

## 3. 技術棧

| 層級 | 建議 |
|---|---|
| 前端 | React 或 Next.js + TypeScript |
| 後端 | Python FastAPI |
| 資料處理 | pandas 優先，保留 Polars 擴充 |
| 資料庫 | PostgreSQL |
| 檔案儲存 | 本機檔案系統與 S3 相容 Adapter |
| 部署 | Docker Compose 優先 |
| API 文件 | OpenAPI |
| 報告 | HTML 為主，PDF 匯出 |

## 4. 前端架構

前端應以工作流程為核心，建議分為：

- 任務首頁。
- 原始資料觀察。
- 資料匯入。
- 資料品質檢查。
- 資料處理。
- 資料視覺化。
- 分析。
- 報告。
- 教師檢視。

前端不得直接實作可信資料處理邏輯。前端可進行即時提示與輸入檢查，但最終結果需由後端驗證。

## 5. 後端模組

### 5.1 身分與課程服務

負責：

- 使用者登入。
- 教師建立學生帳號。
- 課程與任務管理。
- 角色權限。

初版使用本機帳號密碼，保留未來串接校務身分驗證介面。

### 5.2 檔案匯入服務

負責：

- 上傳檔案驗證。
- CSV/XLSX 解析。
- 工作表選擇。
- 欄位推斷。
- 匯入紀錄。
- 原始檔保存。

### 5.3 資料品質服務

負責：

- 欄位統計。
- 缺值。
- 重複。
- 類別分布。
- 異常值。
- 型態推斷衝突。
- 品質檢查結果版本化。

### 5.4 資料處理服務

負責：

- 執行資料轉換。
- 產生資料版本。
- 保存操作鏈。
- 支援還原與重做。
- 回傳處理前後差異。

所有資料處理操作都必須是非破壞性的。原始資料不可覆寫。

### 5.5 視覺化服務

負責：

- 保存圖表設定。
- 依資料版本取樣或聚合。
- 檢查圖表設定合理性。
- 產生圖表資料。

圖表的顯示由前端完成，圖表資料與設定由後端保存。

### 5.6 分析服務

負責：

- 描述統計。
- 群組比較。
- 趨勢分析。
- 相關性。
- 簡單線性迴歸。
- 分析參數保存。
- 結果版本化。

### 5.7 報告服務

負責：

- 彙整資料集資訊。
- 彙整處理歷程。
- 彙整圖表與分析結果。
- 保存學生文字。
- 產生 HTML。
- 匯出 PDF。

報告不得覆寫學生撰寫內容。

### 5.8 提示服務

負責：

- 依任務、模組與提示層級提供提示。
- 記錄提示使用歷程。
- 控制教師設定的最高提示層級。

## 6. 資料模型概要

核心實體：

- User。
- Role。
- Course。
- Assignment。
- Dataset。
- DatasetVersion。
- UploadedFile。
- ImportSession。
- DataSnapshot。
- TransformationStep。
- Visualization。
- AnalysisRun。
- StudentResponse。
- HintUsage。
- Report。
- ReportVersion。
- AuditEvent。

## 7. DataSnapshot 設計

建議採混合策略：

- 保存原始資料。
- 保存所有操作鏈。
- 在重要節點保存資料快照。
- 每個資料處理函式需有版本。

優點：

- 可重現。
- 可還原。
- 儲存量可控。
- 可追蹤操作歷程。

## 8. API 原則

API 採版本化：

```text
/api/v1/auth
/api/v1/courses
/api/v1/assignments
/api/v1/datasets
/api/v1/imports
/api/v1/snapshots
/api/v1/transformations
/api/v1/visualizations
/api/v1/analyses
/api/v1/hints
/api/v1/reports
/api/v1/admin
/api/v1/health
```

要求：

- 結構化錯誤回應。
- 請求追蹤 ID。
- 所有修改操作檢查權限。
- 長時間工作回傳 job_id。
- OpenAPI 規格自動產生。

## 9. 教學流程與資料引擎分離

資料引擎只回答：

- 目前資料長什麼樣。
- 操作後資料如何改變。
- 統計結果是什麼。
- 圖表資料如何產生。

教學流程控制：

- 何時解鎖下一步。
- 哪些提示可見。
- 哪些欄位需要學生填寫理由。
- 哪些操作為任務必經項目。

兩者不得混在同一層，避免未來改教案時需要改資料處理邏輯。

## 10. 部署抽象

所有環境差異透過設定：

- DATABASE_URL。
- STORAGE_BACKEND。
- STORAGE_PATH。
- S3_ENDPOINT。
- S3_BUCKET。
- AUTH_MODE。
- ALLOWED_ORIGINS。
- MAX_UPLOAD_SIZE。
- MAX_DATA_ROWS。
- REPORT_RENDERER。

程式不得寫死：

- 主機名稱。
- 連接埠。
- 密碼。
- 雲端供應商。
- 絕對檔案路徑。
