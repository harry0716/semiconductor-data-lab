# 部署設計

## 1. 部署目標

本系統需能部署於不同環境，包含教師單機、校內伺服器、一般網站與雲端平台。部署設計必須保持雲端平台中立，不將核心功能綁定特定供應商。

## 2. 支援部署型態

### 2.1 模式 A：單機教學部署

適合：

- 教師電腦。
- 實驗室伺服器。
- 校內區域網路。

配置：

- Docker Compose。
- 前端服務。
- 後端服務。
- PostgreSQL。
- 本機檔案儲存或 MinIO。

### 2.2 模式 B：一般網站部署

適合：

- 公開網站。
- 校內網站。
- 小班級使用。

配置：

- 前端靜態部署或 Node 服務。
- 後端容器。
- 託管 PostgreSQL。
- S3 相容儲存。
- HTTPS 反向代理。

### 2.3 模式 C：雲端可擴展部署

適合：

- 多班級。
- 多教師。
- 較高同時使用量。

配置：

- 容器平台。
- 獨立 API 服務。
- 背景工作節點。
- 託管資料庫。
- 物件儲存。
- 日誌與監控服務。

## 3. 環境變數

所有環境差異必須由環境變數控制。

必要變數：

- APP_ENV。
- DATABASE_URL。
- STORAGE_BACKEND。
- STORAGE_PATH。
- S3_ENDPOINT。
- S3_BUCKET。
- S3_ACCESS_KEY_ID。
- S3_SECRET_ACCESS_KEY。
- MAX_UPLOAD_SIZE。
- MAX_DATA_ROWS。
- ALLOWED_ORIGINS。
- AUTH_MODE。
- SESSION_SECRET。
- LOG_LEVEL。
- REPORT_RENDERER。
- WORKER_MODE。

不得在程式碼內寫死：

- 主機名稱。
- 連接埠。
- 網址。
- 資料庫密碼。
- 儲存路徑。
- 雲端供應商。
- 開發環境來源網址。

## 4. 容器化需求

未來開發需提供：

- 前端 Dockerfile。
- 後端 Dockerfile。
- docker-compose.yml。
- `.env.example`。
- 健康檢查。
- 資料庫遷移腳本。
- 初始化資料腳本。
- 備份與還原說明。

## 5. 檔案儲存

開發環境：

- 本機目錄。

單機或校內部署：

- 本機目錄或 MinIO。

正式網站：

- S3 相容物件儲存。
- AWS S3。
- Cloudflare R2。
- 其他相容服務。

應以 Storage Adapter 隔離實作，不讓業務邏輯依賴特定儲存供應商。

## 6. 資料庫

建議：

- 初期即使用 PostgreSQL。
- 開發透過 Docker Compose 啟動。
- 測試環境使用獨立測試資料庫。
- 正式環境使用託管 PostgreSQL 或校內 PostgreSQL。

必要能力：

- 遷移。
- 備份。
- 還原。
- 連線池。
- 最小權限帳號。

## 7. 背景工作

初版可先保留背景工作介面。下列任務未來適合背景化：

- 大型檔案解析。
- 大量資料品質檢查。
- PDF 產生。
- 大型分析。
- 教師批次匯出。

## 8. 健康檢查

至少提供：

- API 健康狀態。
- 資料庫連線狀態。
- 檔案儲存可用狀態。
- 背景工作狀態。
- 版本資訊。

## 9. 備份與還原

需涵蓋：

- PostgreSQL 資料。
- 上傳原始檔。
- 資料快照。
- 報告檔案。
- 環境設定範本。

還原驗證需在全新環境完成一次學生流程。

## 10. 部署驗收

部署完成需驗證：

- 全新環境可啟動。
- 前端可連後端。
- 後端可連資料庫。
- 上傳與儲存可用。
- 可完成一個學生流程。
- 可產生報告。
- 備份可還原。
- 無硬編碼本機路徑。
