# 開發流程

## 1. 開發策略

本系統採階段式開發。每一階段都需完成規格、實作、測試、文件、教學驗證與回歸檢查後，才可進入下一階段。

目前階段只建立文件。正式開發前須先通過文件審查與階段 0。

## 2. 階段 0：需求凍結與現況盤點

工作：

- 閱讀既有 `codex_dev_docs_v2`。
- 盤點原系統架構與可重用資產。
- 確認不得修改區域。
- 確認新系統資料夾與部署目標。
- 確認 MVP 範圍。
- 確認第一份虛擬資料集。

產出：

- 現況盤點報告。
- 重用與隔離清單。
- 最終規格 v1.0。
- 開發風險清單。

通過條件：

- 原系統不受影響。
- 新系統範圍清楚。
- MVP 功能已確認。
- 技術棧已確認。

## 3. 階段 1：架構與骨架

工作：

- 建立前後端專案骨架。
- 建立資料庫遷移機制。
- 建立 Docker Compose。
- 建立環境設定範本。
- 建立健康檢查。
- 建立測試基礎架構。

通過條件：

- 新系統可獨立啟動。
- 前後端可互相連線。
- 資料庫遷移成功。
- 健康檢查通過。
- 原系統可正常啟動。

## 4. 階段 2：資料集與匯入

工作：

- 建立資料生成器。
- 建立第一份虛擬資料集。
- 完成 CSV/XLSX 匯入。
- 完成資料預覽。
- 完成欄位推斷。
- 完成檔案安全檢查。

通過條件：

- 正常 CSV/XLSX 可匯入。
- 錯誤格式可被拒絕。
- 異常值與缺值可被保留。
- 原始資料不可被覆寫。
- 匯入紀錄可追蹤。

## 5. 階段 3：資料品質與資料處理

工作：

- 建立品質檢查引擎。
- 建立資料轉換引擎。
- 建立操作歷程。
- 建立還原與重做。
- 建立資料版本。

通過條件：

- 每一步可重現。
- 每一步可還原。
- 筆數變化正確。
- 型態轉換可檢查。
- 失敗操作不破壞現有資料。

## 6. 階段 4：視覺化

工作：

- 建立圖表設定介面。
- 建立圖表資料 API。
- 保存圖表設定。
- 建立圖表合理性檢核。
- 支援圖表匯入報告。

通過條件：

- 至少五種圖表可用。
- 圖表使用正確資料版本。
- 圖表可保存與重新載入。
- 不合理設定能提供提示。
- 大量資料採抽樣或聚合。

## 7. 階段 5：分析與解讀

工作：

- 描述統計。
- 群組比較。
- 趨勢分析。
- 相關性分析。
- 簡單線性迴歸。
- 學生解讀輸入。
- 基本合理性檢核。

通過條件：

- 統計結果可重現。
- 無效欄位組合被阻擋。
- 缺值處理策略明確。
- 分析參數有紀錄。
- 系統不自動取代學生結論。

## 8. 階段 6：提示、報告與教師端

工作：

- 分層提示。
- 報告組合。
- HTML/PDF 匯出。
- 教師檢視頁。
- 學生歷程頁。
- 基礎評分輔助。

通過條件：

- 報告引用正確圖表與分析。
- 學生文字不被系統覆寫。
- 教師可查看完整歷程。
- 提示使用紀錄正確。
- HTML 與 PDF 內容一致。

## 9. 階段 7：安全、效能與部署

工作：

- 安全測試。
- 負載測試。
- 部署測試。
- 備份與還原。
- 錯誤監控。
- 正式環境文件。

通過條件：

- Docker 部署通過。
- 全新環境可依文件完成部署。
- 檔案攻擊測試通過。
- 主要 API 有速率限制。
- 備份可還原。
- 環境設定無硬編碼。

## 10. 階段 8：教學驗收

工作：

- 以教師身分完成示範。
- 以學生身分完成完整實驗。
- 模擬低程度學生操作。
- 模擬錯誤操作。
- 檢查是否過度自動化。
- 檢查是否有無效操作負擔。

通過條件：

- 學生實際經歷完整資料流程。
- 系統未直接暴露完整答案。
- 重要操作有明確回饋。
- 教師可追蹤學生決策歷程。
- 報告可反映真實操作。

## 11. 修改流程

每個功能修改依序進行：

```text
主代理建立任務規格
    ↓
實作代理完成模組
    ↓
實作代理執行自測
    ↓
驗證代理建立反向測試
    ↓
教學設計代理檢查教學目標
    ↓
安全與部署代理檢查風險
    ↓
主代理整合
    ↓
全域回歸測試
```

## 12. 開發啟動條件

正式撰寫系統前需確認：

- 文件集已審查通過。
- MVP 範圍已確認。
- 技術棧已確認。
- 第一份虛擬資料集主題已確認。
- 登入方式已確認。
- 報告格式已確認。
- AI 功能邊界已確認。
- 原版本不可修改範圍已確認。
- 子代理分工已確認。
