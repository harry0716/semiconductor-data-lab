# 安全規格

## 1. 安全目標

本系統包含使用者帳號、學生作業、上傳檔案、資料處理結果與報告，因此需將所有使用者輸入與上傳內容視為不可信。

安全目標：

- 防止未授權存取。
- 防止上傳檔案攻擊。
- 防止常見 Web 漏洞。
- 保護學生資料與報告。
- 避免錯誤訊息與日誌洩漏敏感資訊。
- 保持部署環境可安全設定。

## 2. 身分與權限

初版登入方式：

- 教師建立學生帳號。
- 帳號密碼登入。
- 保留未來串接校務身分驗證介面。

權限原則：

- 學生只能查看自己的資料與任務。
- 教師只能查看自己課程中的學生資料。
- 管理功能需獨立權限。
- 所有修改操作都需後端驗證權限。
- 前端隱藏按鈕不等於權限控制。

## 3. 密碼與 Session

要求：

- 密碼使用安全雜湊。
- Session secret 由環境變數提供。
- Cookie 設定 HttpOnly、Secure、SameSite。
- 登出需使 session 失效。
- 登入錯誤需有速率限制。

## 4. 檔案上傳安全

支援格式：

- CSV。
- XLSX。

禁止：

- XLSM。
- 可執行檔。
- 巨集。
- 不明壓縮格式。

檢查：

- 副檔名。
- MIME 類型。
- 檔案大小。
- 解析時間。
- 欄位數量。
- 資料列數量。
- XLSX 壓縮炸彈風險。
- 空白或重複欄位名稱。

儲存：

- 使用系統產生檔名。
- 不信任使用者原始檔名。
- 不使用使用者提供路徑。
- 上傳檔案與可執行程式隔離。

## 5. CSV 與試算表公式注入

輸出 CSV、XLSX 或報告表格時，需處理以以下字元開頭的欄位值：

- `=`
- `+`
- `-`
- `@`
- tab
- carriage return

避免使用者下載後在試算表中觸發公式。

## 6. Web 安全

需防護：

- SQL Injection。
- XSS。
- CSRF。
- 路徑穿越。
- SSRF。
- 開放重新導向。
- 越權存取。
- 不安全直接物件參照。

要求：

- 使用參數化查詢或 ORM。
- 輸出內容預設跳脫。
- 所有物件存取檢查擁有權。
- API 修改操作需有 CSRF 或同等防護。
- 安全標頭。
- CORS 僅允許設定中的來源。

## 7. API 安全

要求：

- 所有 API 有版本。
- 修改操作需驗證身分與權限。
- 錯誤回應不得洩漏堆疊與連線資訊。
- 大型操作需速率限制。
- 上傳與分析 API 需限制資源。
- 所有請求需可追蹤 request_id。

## 8. 資料隔離

需隔離：

- 不同學生的上傳檔案。
- 不同學生的資料快照。
- 不同學生的報告。
- 不同課程的教師資料。

所有資料查詢都需帶入使用者與課程權限條件。

## 9. 日誌

應記錄：

- 登入失敗。
- 權限拒絕。
- 上傳失敗。
- 檔案解析失敗。
- 資料處理失敗。
- 報告生成失敗。
- 系統錯誤。

不得記錄：

- 密碼。
- Session token。
- API key。
- S3 secret。
- 完整敏感檔案內容。

## 10. 依賴安全

未來開發需定期執行：

- 前端依賴弱點掃描。
- 後端依賴弱點掃描。
- 容器映像弱點掃描。
- 授權條款檢查。

## 11. 安全測試清單

最低測試：

- 上傳偽裝副檔名。
- 上傳超大檔案。
- 上傳 XLSM。
- 上傳 CSV 公式。
- 嘗試路徑穿越。
- 嘗試學生互看資料。
- 嘗試學生進入教師 API。
- 嘗試 XSS 文字輸入。
- 嘗試 SQL Injection。
- 檢查錯誤訊息是否洩漏資訊。

## 12. 安全完成定義

安全相關功能需同時滿足：

- 有威脅模型。
- 有防護設計。
- 有測試案例。
- 有失敗處理。
- 有日誌。
- 有部署設定。
- 有文件。
