# 代理分工與工作流

## 1. 目的

本文件定義多代理開發時的角色、責任、交付物、審查流程與禁止事項。目標是降低大型系統開發時的盲點，尤其避免同一代理同時產生資料、撰寫分析邏輯並宣告驗證成功。

## 2. 主代理

職責：

- 維護總體規格。
- 分派任務。
- 控制模組邊界。
- 審查子代理產出。
- 整合程式碼與文件。
- 執行全域回歸測試。
- 確保不影響原系統。

主代理不得直接接受未驗證的子代理產出。

## 3. 既有系統盤點代理

職責：

- 閱讀 `codex_dev_docs_v2`。
- 盤點原系統結構。
- 辨識可重用資產。
- 辨識不可修改區域。
- 找出潛在耦合與風險。

交付物：

- 現況盤點。
- 重用清單。
- 禁止修改清單。
- 風險清單。

## 4. 教學設計代理

職責：

- 驗證功能是否支持教學目標。
- 檢查是否過度自動化。
- 設計學生必要操作。
- 設計提示層級。
- 設計教學檢核點。
- 檢查報告結構。

交付物：

- 教學流程。
- 模組學習目標。
- 學生操作清單。
- 教學風險清單。

## 5. 資料與分析代理

職責：

- 設計虛擬資料集。
- 建立資料 schema。
- 設計資料異常。
- 建立資料生成器。
- 定義參考分析結果。
- 驗證統計關係。

交付物：

- 資料 schema。
- 生成器。
- 測試資料。
- 參考答案。
- 統計驗證報告。

此代理不得單獨宣告資料與分析驗證完成，必須由測試與驗證代理交叉確認。

## 6. 後端與資料處理代理

職責：

- API。
- 資料庫。
- 檔案匯入。
- 資料品質檢查。
- 資料轉換。
- 操作歷程。
- 分析服務。
- 報告資料組合。

交付物：

- 後端程式碼。
- API 文件。
- 單元測試。
- 資料庫遷移。

## 7. 前端與互動代理

職責：

- 學生操作介面。
- 教師介面。
- 資料表格。
- 圖表設定。
- 步驟導覽。
- 錯誤回饋。
- 響應式設計。

交付物：

- 前端程式碼。
- 元件測試。
- 介面狀態規格。
- 可用性檢核。

## 8. 安全與部署代理

職責：

- 威脅模型。
- 上傳檔案安全。
- 權限檢查。
- Docker。
- CI/CD。
- 環境變數。
- 備份還原。
- 部署文件。

交付物：

- 安全檢查表。
- 容器設定。
- 部署文件。
- 安全測試結果。

## 9. 測試與驗證代理

職責：

- 不參與同一功能的核心實作。
- 依規格建立測試。
- 執行整合測試。
- 執行端到端測試。
- 驗證資料分析結果。
- 驗證原系統未被破壞。
- 驗證部署重現性。

交付物：

- 測試計畫。
- 測試案例。
- 測試報告。
- 缺陷清單。
- 回歸結果。

## 10. 功能交付流程

每個功能依下列流程：

```text
需求確認
    ↓
任務切分
    ↓
實作代理開發
    ↓
實作代理自測
    ↓
驗證代理反向測試
    ↓
教學設計審查
    ↓
安全與部署審查
    ↓
主代理整合
    ↓
全域回歸
    ↓
文件更新
```

## 11. 禁止流程

禁止：

- 同一代理生成資料、寫分析函式、建立參考答案並宣告驗證成功。
- 未經教學設計代理審查就新增自動化答案功能。
- 未經安全代理審查就新增檔案上傳或權限功能。
- 未經部署代理審查就引入特定雲端服務依賴。
- 未經主代理整合就合併跨模組修改。

## 12. 審查清單

每次交付需確認：

- 是否符合產品規格？
- 是否保留學生必要操作？
- 是否完整記錄歷程？
- 是否可重現？
- 是否可還原？
- 是否有測試？
- 是否有安全風險？
- 是否影響部署？
- 是否影響原系統？
- 是否更新文件？
